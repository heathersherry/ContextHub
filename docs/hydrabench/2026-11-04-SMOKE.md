# HyDRA-Bench: first Deep Agents + ContextHub smoke test

Both hybrid tool paths were exercised against the original SQLite database and
real ContextHub retrieval. This establishes integration feasibility. It does not
establish benchmark accuracy: A2S has an aggregation/tie ambiguity, and the first
S2A attempt answered from prior knowledge without retrieving text.

## Results

All times below are Hong Kong time (UTC+8), 2026-11-04. Durations cover agent
execution, excluding source acquisition and corpus import.

| Case / attempt | Start | Time | SQL calls | Schema searches | Text searches | Observation |
| --- | --- | --- | --- | --- | --- | --- |
| `dev_19` A2S | 11:01:58 | 37.008 s | 8 | 1 | 2 | SQL → text retrieval worked; calcium/second-messenger claim matches the reference, but SQL aggregation differs |
| `dev_39` S2A, initial | 11:02:35 | 16.056 s | 4 | 1 | 0 | All 6 bond IDs correct; did not exercise text → SQL |
| `dev_39` S2A, evidence rerun | 11:03:41 | 22.350 s | 4 | 1 | 1 | Retrieved supporting text before the dependent SQL; all 6 bond IDs correct |

No tool execution errors occurred in these three attempts. The SQLite SHA-256
was unchanged before and after every attempt. All 1,494 text contexts and all
4 table contexts had non-null embeddings. The focused verification suite passed
37 tests: read-only SQL, timeout, truncation, annotation isolation, and the
existing Deep Agents adapter tests.

Answers were inspected by the coding assistant against the references, retrieved
evidence and SQL results. S2A bond IDs were also compared as sets. This was **not**
the paper's GPT-o4-mini judge or an independent human annotation. No `2/2`,
Accavg or Best@8 score is reported. The streaming provider supplied no token
usage metadata, so token counts and cost are unknown, not zero.

## What the traces show

### A2S: integration works, but the aggregation is not reference-equivalent

The agent queried SQLite, identified calcium among the minimum-count elements,
then searched for calcium's role in signaling. The calcium abstract was ranked
second behind a phosphorus passage; it nevertheless supplied the second-messenger
statement cited in the final answer. No ranking changes were made after this run.

The generated SQL used `COUNT(*)` over atoms. The reference uses
`COUNT(DISTINCT molecule_id)`. A separate, post-run SQL audit found:

| Element | Non-carcinogenic molecules containing it | Atoms in those molecules |
| --- | --- | --- |
| `ca` | 1 | 1 |
| `i` | 1 | 3 |
| `k` | 1 | 1 |
| `pb` | 1 | 1 |

Thus the agent correctly noticed a three-way tie **under its atom-count
interpretation**. Under the reference's molecule-count interpretation, four
elements tie. The reference SQL sorts only by the count and takes `LIMIT 1`,
without an explicit secondary tie-break, returning `ca` on this database.
The question does not spell out that tie-break. Matching the calcium explanation
alone therefore does not demonstrate equivalent SQL reasoning.

The agent's final answer also included extra biological details beyond its cited
abstract. The review confirms the core calcium/second-messenger statement, not
independent support for every extra detail.

### S2A: a correct answer can hide skipped retrieval

The first attempt recognized phosphorus from prior knowledge and went directly
to SQL. It returned the six reference bond IDs, but that was insufficient for
this integration goal.

For the second attempt, only a **generic** evidence requirement was added:
verify external factual premises in retrieved text before using them as SQL
filters. No reference entity, SQL, decomposition or answer was added. The same
case, corpus, database, model and retrieval settings were retained.

The rerun searched the resource corpus, obtained phosphorus passages including
the abstract at `ctx://team/engineering/hydra/kilt/23318/0000` version 1, then
queried phosphorus–nitrogen bonds. The final set matched the reference exactly:

`TR032_2_3`, `TR032_3_5`, `TR058_1_3`, `TR058_1_4`, `TR058_1_5`, `TR298_1_5`.

The search query already included the hypothesized word “phosphorus.” This
demonstrates verification through retrieval before dependent SQL, not that the
model needed retrieval to discover the entity.

Neither case called the separate `contexthub_read` tool. Search already returned
the full stored passage in L1, which is identical to L2 in this smoke corpus.
The evidence was visible, but the prompt's requested separate L2-read step was
not followed. Each text search returned 3 hits; the 10-search limit was not
approached. Schema searches used the native top-5 default/request and returned
the four available tables.

## Runtime and data

- Branch/worktree: `codex/hydra-smoke`, based on
  `865be345c18432f7ae6e744c3800f047b1cccf82`. The new harness and records are
  worktree changes. The primary checkout's unrelated changes were not edited.
- Agent: Deep Agents `0.7.32`, model `deepseek-v4-pro-0813`, temperature 0,
  thinking disabled; native ContextHub SDK tools plus a bound read-only SQLite
  execution tool. Package versions and exact prompts are in every trace.
- Retrieval: ContextHub `text-embedding-v4`, 1,536 dimensions, existing keyword
  reranking. No per-question retriever tuning or memory/feedback write tools.
- SQLite: original BIRD `toxicology.sqlite`, 2,678,784 bytes, SHA-256
  `f5fa7f21af1ad878ff8fef1b0582b8cb2d7ed63dbac65ff16d2ba05667650c5b`.
- ContextHub: isolated `contexthub-hydra-smoke` PostgreSQL container on local
  port `55433`, non-superuser application role; API on `127.0.0.1:18082`.
  Propagation/lifecycle workers were disabled. PostgreSQL contains passages and
  table metadata; benchmark rows remain in SQLite.
- Cases: first `toxicology` dev question of each type in release order, fixed
  before any model run. Agent input contains only `db_id` and `final_question`.
- Corpus: 20 articles (the first 20 chemical elements), 2,273 original paragraphs
  from the [s-nlp KILT mirror](https://huggingface.co/datasets/s-nlp/kilt), converted
  to 1,494 passages; 2 passages hit the 3,000-character cap. Topic selection was
  informed by these cases and makes retrieval easier than full-corpus evaluation.
- Acquisition: title columns were scanned to locate exact article row ranges;
  full paragraphs were fetched by row position. Every article had contiguous
  paragraph IDs from zero, with no API-truncated cells. All paragraphs of Argon
  and Aluminium matched the official KILT raw articles after trimming surrounding
  whitespace. This is a two-article spot check, not full mirror verification.
- Original BIRD column-description CSVs accompany schemas in ContextHub. This is
  additional metadata beyond the paper's SQLite-only schema discovery interface.

The initial importer request used the document-ingestion URI namespace with the
generic context API and was rejected before creating contexts. It was corrected
to the existing `ctx://team/engineering/...` contract; the full import then
completed. This setup correction did not change the ContextHub server or search
implementation. Some corpus acquisition requests also timed out; the saved
source subset is complete for the 20 declared articles.
